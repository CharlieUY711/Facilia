# PROMPT GEO-00 — Documento Funcional y Arquitectura del Módulo GEO

> **Rol**
>
> Actúa como un **Principal Enterprise Software Architect** especializado en SaaS multi-tenant, Workforce Management, Field Service Management (FSM), Geolocation Platforms, Mobile Workforce, DDD y Clean Architecture.
>
> FACILIA incorpora un nuevo módulo independiente denominado:
>
> # GEO — Geopositioning & Workforce Control
>
> Este módulo será responsable de gestionar información geográfica operacional del personal utilizando dispositivos móviles provistos por la empresa.
>
> **No generar código.**
> **No generar SQL.**
> **No implementar funcionalidades.**
>
> El objetivo de esta etapa es definir el documento funcional y la arquitectura base del módulo.

---

# 1. Objetivo del módulo

Definir una plataforma de geolocalización operacional que permita relacionar:

```
Empleado
+
Dispositivo
+
Ubicación GPS
+
Horario laboral
+
Orden de Trabajo
+
Ubicación del Cliente
```

para validar la correcta ejecución de servicios.

---

# 2. Propósito empresarial

GEO debe permitir que FACILIA pueda ofrecer:

* trazabilidad operacional;
* control de cumplimiento horario;
* evidencia de presencia;
* transparencia hacia clientes corporativos;
* mejora de supervisión.

---

# 3. Principio arquitectónico

GEO es un módulo independiente.

## GEO NO administra:

* contratos;
* servicios;
* órdenes;
* planificación;
* empleados;
* clientes.

Estos pertenecen a otros dominios.

---

## GEO administra:

* dispositivos;
* posiciones;
* sesiones de seguimiento;
* geocercas;
* eventos geográficos;
* validaciones de presencia.

---

# 4. Relación con otros módulos

## Directory

Fuente maestra de:

* personas;

---

## Operations

Fuente de:

* órdenes de trabajo;

## Contract Management

Fuente de:

* ubicaciones del cliente;
* sedes;

---

## Library

Uso futuro para:

* reportes;
* evidencias;
* documentación.

---

# 5. Casos de uso principales

## Caso 1 — Inicio de jornada

Empleado inicia su actividad.

Sistema:

* valida usuario;
* identifica dispositivo;
* inicia sesión GEO.

---

## Caso 2 — Registro de ubicación

Durante la jornada:

Sistema registra:

* posición;
* fecha;
* hora;
* precisión.

---

## Caso 3 — Llegada a cliente

Empleado llega a una ubicación autorizada.

Sistema genera:

```
EmployeeArrivedLocation
```

---

## Caso 4 — Permanencia

Sistema valida:

* tiempo dentro de zona;
* relación con tarea asignada.

---

## Caso 5 — Salida

Sistema registra:

```
EmployeeLeftLocation
```

---

## Caso 6 — Incumplimiento

Ejemplo:

Orden:

08:00 Cliente A

GPS:

08:45 llegada

Generar:

```
LateArrivalDetected
```

---

# 6. Modelo conceptual inicial

Definir los siguientes conceptos:

---

# Device

Representa un dispositivo empresarial.

Responsabilidad:

* identificar celular;
* asociarlo a usuario;
* controlar estado.

---

# LocationRecord

Representa una posición registrada.

Datos:

* latitud;
* longitud;
* precisión;
* timestamp.

---

# TrackingSession

Representa un período activo de seguimiento.

Ejemplo:

```
Empleado:
Juan Pérez

Inicio:
08:00

Fin:
17:00
```

---

# Geofence

Representa una zona autorizada.

Ejemplos:

* cliente;
* oficina;
* depósito.

---

# PresenceEvent

Representa un evento geográfico.

Ejemplos:

* entrada;
* salida;
* permanencia.

---

# LocationValidation

Resultado de comparar:

```
Ubicación esperada
+
Ubicación real
+
Horario
```

---

# 7. Reglas de negocio iniciales

Definir:

---

## Regla de jornada

La captura de ubicación solo debe ejecutarse dentro de una sesión activa.

---

## Regla de geocerca

Una persona se considera presente cuando:

```
Distancia GPS <= radio permitido
```

---

## Regla de tarea

Una ubicación solo se valida si existe relación con:

* orden;
* servicio;
* asignación.

---

## Regla de auditoría

Toda acción debe registrar:

* usuario;
* fecha;
* organización.

---

# 8. Privacidad y seguridad

Definir arquitectura considerando:

* uso corporativo del dispositivo;
* transparencia hacia empleados;
* permisos por rol;
* acceso restringido;
* trazabilidad.

El sistema debe permitir:

* activar/desactivar seguimiento;
* definir horarios;
* controlar quién visualiza ubicaciones.

---

# 9. Multi-tenancy

* múltiples organizaciones;
* separación de datos;
* permisos por organización;
* configuración independiente.

✅ crear geocercas

# 13. Fuera de alcance

No implementar:

* rutas;
* navegación;
* optimización;
* IA;
* reconocimiento facial;
* biometría;
* seguimiento permanente;
* gestión de flota.
