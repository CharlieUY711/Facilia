# PROMPT GEO-01 — Modelo de Dominio, Base de Datos y Persistencia del Módulo GEO

> **Rol**
>
> Actúa como un **Senior Domain Architect** especializado en DDD, PostgreSQL, sistemas SaaS multi-tenant, geolocalización empresarial, Workforce Management y Clean Architecture.
>
> El documento funcional y arquitectura del módulo **GEO — Geopositioning & Workforce Control** ya fue aprobado en GEO-00.
>
> Esta etapa debe diseñar el modelo técnico del dominio y la persistencia.
>
> **No implementar todavía frontend.**
>
> **No implementar aplicación móvil.**
>
> **No implementar mapas.**
>
> **No modificar módulos externos.**
>
> El objetivo es crear una base sólida para el desarrollo posterior.

---

# Objetivo

Diseñar el modelo de dominio y persistencia necesario para soportar:

* dispositivos corporativos;
* usuarios asociados;
* captura de posiciones;
* sesiones de seguimiento;
* geocercas;
* eventos de presencia;
* validaciones contra tareas operativas.

---

# Principios de diseño

## GEO es dueño únicamente de información geográfica.

No duplicar:

* personas;
* organizaciones;
* clientes;
* órdenes;
* contratos.

Toda referencia externa debe realizarse mediante identificadores.

---

# Bounded Context

Definir:

```text
GEO — Geopositioning & Workforce Control
```

Responsabilidades:

* tracking;
* ubicación;
* presencia;
* validación geográfica.

---

# Modelo de dominio

Diseñar las siguientes entidades.

---

# 1. Device

Representa un dispositivo móvil corporativo.

Campos conceptuales:

* id;
* organization_id;
* device_identifier;
* nombre;
* modelo;
* sistema operativo;
* versión;
* usuario asignado;
* estado;
* última conexión.

Estados:

```text
ACTIVE

INACTIVE

LOST

BLOCKED

RETIRED
```

---

# 2. TrackingSession

Representa una sesión activa de seguimiento.

Ejemplo:

Empleado inicia jornada.

Campos:

* id;
* organization_id;
* employee_id;
* device_id;
* inicio;
* fin;
* estado.

Estados:

```text
ACTIVE

PAUSED

ENDED

CANCELLED
```

---

# 3. LocationRecord

Representa una posición capturada.

Campos:

* id;
* organization_id;
* device_id;
* employee_id;
* latitude;
* longitude;
* accuracy;
* altitude (opcional);
* speed (opcional);
* timestamp.

Consideraciones:

Debe estar preparado para alto volumen de registros.

---

# 4. Geofence

Representa una zona geográfica.

Ejemplos:

* cliente;
* oficina;
* depósito.

Campos:

* id;
* organization_id;
* nombre;
* tipo;
* referencia externa;
* centro;
* radio;
* estado.

Tipos:

```text
CLIENT_LOCATION

OFFICE

WAREHOUSE

CUSTOM
```

---

# 5. PresenceEvent

Representa un evento dentro de una geocerca.

Ejemplos:

Empleado llega.

Empleado sale.

Campos:

* id;
* employee_id;
* device_id;
* geofence_id;
* tipo;
* timestamp;
* location_record_id.

Tipos:

```text
ENTER

EXIT

STAY

UNKNOWN
```

---

# 6. LocationValidation

Resultado del cruce entre GEO y otros módulos.

Ejemplo:

Orden:

08:00 Cliente A

Ubicación:

08:05 Cliente A

Resultado:

VALIDATED

Campos:

* id;
* organization_id;
* employee_id;
* work_order_id;
* geofence_id;
* resultado;
* fecha;
* diferencia horaria.

Estados:

```text
VALIDATED

PARTIAL

FAILED

PENDING
```

---

    +--- Device

    |

    |

# Integración con Directory

No crear tabla Employee.

Guardar únicamente:

```text
employee_id
user_id
organization_id
```

Directory es la fuente maestra.

---

# Integración con Operations

No crear tabla WorkOrder.

Guardar únicamente:

```text
work_order_id
service_id
location_id
```

Operations mantiene la propiedad.

---

# Base de datos

Diseñar migraciones PostgreSQL.

Requerimientos:

* UUID como clave primaria.
* timestamps estándar.
* soft delete cuando corresponda.
* organization_id obligatorio.
* auditoría.

* backend GEO;
* APIs;
