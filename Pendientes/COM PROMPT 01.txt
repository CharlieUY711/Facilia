# PROMPT COM-01 — Modelo de Dominio, Persistencia y Arquitectura Técnica del Módulo COM

> **Rol**
>
> Actúa como un **Enterprise Domain Architect** especializado en DDD, Clean Architecture, sistemas SaaS multi-tenant, comunicaciones empresariales, integración con WhatsApp Business API y plataformas de Field Service Management.
>
> El módulo:
>
> # COM — Communications Hub
>
> cuenta con:
>
> * COM-00 — Documento Maestro Funcional.
>
> Esta etapa debe definir el modelo técnico del dominio y la persistencia.
>
> **No implementar código todavía.**
>
> **No implementar Twilio todavía.**
>
> **No crear frontend.**
>
> **No modificar Operations, Directory ni Library.**
>
> El objetivo es crear una base arquitectónica estable para la implementación posterior.

---

# Objetivo

Diseñar el dominio COM para gestionar:

* comunicaciones operativas;
* conversaciones;
* mensajes;
* plantillas;
* reglas automáticas;
* respuestas;
* evidencias;
* integraciones externas.

---

# Principio fundamental

COM administra comunicaciones.

No administra:

* órdenes de trabajo;
* empleados;
* clientes;
* archivos;
* contratos.

Debe referenciar esos dominios.

---

# Bounded Context

Definir:

```text
COM — Communications Hub
```

Responsabilidad:

Transformar eventos operativos en comunicaciones trazables.

Domain

# Modelo de dominio

Implementar conceptualmente:

---

# 1. Conversation

## Responsabilidad

Representar una comunicación operacional relacionada con un contexto.

Ejemplo:

```text
Orden 000123

Empleado:
Juan Pérez

Cliente:
Empresa ABC
```

---

## Campos

Definir:

* id;
* organization_id;
* employee_id;
* work_order_id;
* channel;
* estado;
* fecha inicio;
* fecha cierre.

---

## Estados

```text
OPEN

CLOSED

ARCHIVED
```

---

# 2. Message

Representa un mensaje individual.

Puede ser:

* enviado;
* recibido.

---

## Tipos

```text
TEXT

IMAGE

DOCUMENT

LOCATION

SYSTEM
```

---

## Dirección

```text
OUTBOUND

INBOUND
```

---

## Estados

```text
CREATED

SENT

DELIVERED

READ

FAILED
```

---

## Campos

Definir:

* conversation_id;
* contenido;
* proveedor;
* external_id;
* timestamp;
* usuario origen.

---

# 3. CommunicationTemplate

Representa una plantilla reutilizable.

Ejemplos:

* asignación de tarea;
* recordatorio;
* solicitud de evidencia.

---

## Campos

* nombre;
* organización;
* tipo;
* contenido;
* variables;
* estado.

---

# 4. CommunicationRule

Define automatizaciones.

Ejemplo:

```text
Evento:

WorkOrderAssigned

Acción:

Enviar WhatsApp
```

---

## Campos

* evento origen;
* plantilla;
* canal;
* destinatario;
* condiciones.

---

# 5. DeliveryRecord

Registra interacción con proveedores externos.

Ejemplo:

Twilio.

---

Campos:

* provider;
* external_message_id;
* estado;
* timestamps.

---

# 6. EvidenceReference

Referencia a evidencias recibidas.

No almacenar archivos.

Library es propietaria.

Guardar:

* library_file_id;
* message_id;
* contexto.

---

# 7. CommunicationPreference

Configuración de comunicación.

Ejemplo:

Empleado:

* WhatsApp habilitado.
* Horario permitido.
